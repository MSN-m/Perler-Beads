# Development Summary - 2026-07-02 16:55

## 本次归档主题

本次主要围绕“编辑画布工具栏”的产品结构进行讨论和原型验证。重点不是改正式编辑逻辑，而是先用 `toolbar-prototype.html` 做一个可交互原型，帮助判断未来工具区是否应该从“三个大入口”改为更接近 Figma 的横向工具栏。

## 关键产品结论

### 1. 工具栏方向调整

原先思路是把编辑能力归为三个大类：

- 画笔
- 橡皮
- 颜色清单

讨论后认为，正式编辑区更像轻量绘图工具，用户需要频繁在工具之间切换。如果只保留三个大按钮，很多常用动作会藏进二级菜单，理解成本和切换负担都偏高。

新的方向更接近 Figma 式横向工具栏：

- 常用工具直接露出
- 复杂功能放下拉
- 重型信息放面板或弹窗

### 2. 当前建议的工具栏结构

主工具栏建议按以下顺序组织：

- 选择 / 拖动画布
- 画笔
- 橡皮
- 吸色
- 当前颜色 / 色板
- 颜色清单
- 撤销
- 重做
- 更多

其中：

- 画笔：点击即单格上色，拖动即连续涂抹，不再单独区分“单点 / 涂抹”。
- 橡皮：点击擦一格，拖动擦一片。
- 按颜色移除：归到橡皮能力里，不再作为独立工具。
- 吸色：独立为高频工具。
- 历史颜色：明确为“最近 5 次吸色记录”，用于快速切换画笔色。
- 撤销 / 重做：作为全局常驻控制，不放入某个工具流程里。
- 更多：承接质量检查、重置图纸等低频功能。

### 3. 暂存区逻辑的产品化表达

之前讨论过“确认 / 取消 / 撤回”的编辑流程。当前更倾向于：

- 用户不感知复杂的暂存区概念
- 所有修改先进入内部暂存
- 界面上只表现为常驻的撤销 / 重做 / 重置

这样比每个工具里出现“完成 / 取消”更轻，也更符合画布编辑习惯。

## 当前状态

### 已完成

- 编辑工具从“三大类入口”转向“横向工具栏”的方案验证。
- 画笔、橡皮、吸色、颜色清单、撤销 / 重做的基础层级已整理。
- 已生成可交互原型用于观察结构和操作感。

### 尚未完成

- 该工具栏尚未接入正式 `index.html` 工作台。
- 原型中的画笔、橡皮、吸色只是交互演示，不修改真实图纸数据。
- 下拉菜单只是结构示意，还没有和真实能力绑定。
- Lucide 图标库尚未真正接入，当前仍以文字 / 简化符号替代。
- 工具栏在 iPad / 手机端的形态尚未重新设计。
- 正式编辑流程中的暂存区、撤销、重做、重置需要结合现有 `AppState.stagedPixelData` 和 `stagedActions` 重新梳理。

## 后续建议

### 下一步优先级

1. 先继续确认 PC 工具栏结构是否满意。
2. 确定后再做 iPad 版本，而不是直接接入正式逻辑。
3. 等 PC / iPad 工具结构稳定后，再进入正式代码改造。

### 正式接入时需要注意

- 不要直接重写现有编辑逻辑。
- 需要先梳理现有 `adjust`、`delete`、`batchReplace`、`edgeSelectionMode` 的互斥关系。
- 新工具栏只是入口重组，底层仍应尽量复用现有能力。
- 撤销 / 重做需要优先复用 `stagedActions` 的现有结构。
- 拖动画布与编辑工具必须继续互斥，避免再次出现移动端无法操作或误触问题。
