## 2. 生成前图片调整（正式功能已实施）

### 行为与数据

- 上传后尺寸、颜色数量设置区新增三项滑块及重置，默认均0；仅生成前展示，编辑阶段不新增调色入口。PC/PAD/手机共用逻辑。
- 图片预览与生成使用同一RGB调整函数；保持源图、透明度及原图对照。默认值走原始数据路径，不改变原生成结果。
- 亮度偏移为数值×12.75，对比度系数为2的“数值/5”次方，饱和度系数为1+数值/10；整数归一化、越界截断，无效输入归0。
- 拖动滑块使用最长边1000px的显示副本并通过requestAnimationFrame更新，不在每次input执行完整拼豆生成；正式生成读取完整裁剪数据。
- 重置只恢复三项数值；返回调整和重新裁剪保留，更换/移除图片归零。效果预设继续保留，像素画结构检测读取未调色图片，实际取样读取调色后的数据。
- 确认生成保存当前参数快照。手动、自动保存及历史版本只记录实际用于当前图纸的参数，不误存未应用的滑块值。
- generationSettings增加可选image-brightness、image-contrast、image-saturation；中性值省略，旧草稿缺失归0，恢复直接采用保存的像素，不重新生成。
- 正式算法未切换。核心文档按实际实现纠正buildPatternPreview及像素画专用分支的调用描述，不将文档修正误记成算法替换。

### 验证及限制

- 实现阶段完整自动检查119项通过、0失败（本轮基线113；新增4项调整函数及2项草稿检查）。Node语法检查与git diff --check通过；无可用ReadLints时使用上述替代。
- 在独立Chromium测试上下文完成真实图片上传、三项调整/重置、源图不变、结果颜色变化、默认结果还原、预览确认像素一致、返回/重裁保留、新图片清零及草稿保存恢复。
- 确认结果按颜色ID、RGB和alpha核对一致；深克隆移除临时groups字段不属于颜色变化。
- PC 1440×960、手机390×844、PAD 820×1180模拟视口无横向溢出；手机颜色数量控件可滚动到达，键盘方向键调整步长1。
- 普通图片的品牌/尺寸/颜色上限及原图/卡通/照片效果已检查；像素画专用分支未用合适素材在本轮浏览器专项覆盖。
- 真实PAD/手机触控及大照片性能尚未验收。模拟视口、纯函数检查不能替代实机。
- 归档阶段仅修改文档并做文档/差异检查，未机械重跑实现阶段已通过的全部测试。

## 3. 回放样片与素材

### 素材与历史边界

- 只读采用本地“草稿1”白猫蓝围兜：64×80、MARD、14色、2708颗有效拼豆，保存原图与4个版本。
- 版本中有两组62格、186格的实际差异，另一组没有像素变化。它们是保存版本差异，不能还原从未记录的逐笔编辑过程。
- 原始图片1280×1922，裁剪区域x126/y195/宽789/高990。复制到独立样片数据，不修改IndexedDB、用户草稿或撤销历史。
- 临时只读提取页、接收辅助脚本及服务已经移除/停止；用户原有数据保留。后续生成样片可使用现有静态sample-data.js和source.png。

### 已生成文件

- outputs/replay-previews/index.html：01简洁渐变、02中心生长、03逐行扫描、04翻牌拼合、05轮廓填色、06斜向光波，两组对比；支持同步播放/暂停、拖动进度、循环、放大和GIF下载。
- outputs/replay-previews/fireworks.html：07一朵大烟花与08五朵小烟花对比，使用同一斜向成图动画。五朵从4.00秒起按约0.08秒间隔接连绽放。
- outputs/replay-previews/3d.html：09空间聚豆、10立体翻牌、11波浪归位，不区分生成和修改，直接使用最终图纸；结尾五朵烟花。当前已暂时放弃，仅保留参考。
- 原2D样片前段是设计的生成展示，后段是保存版本差异；全长5秒、结尾保留成图。三种选定2D预设尚未全部重新组合五朵烟花并导出；第08版已有斜向光波加五朵烟花。
- 产物还包括对应11个GIF、source.png、sample-data.js、final-frame.png及三张3D过程静帧；不加入正式首页或编辑器入口。

### 实现、验证与性能

- 本地Canvas/JavaScript绘制，无新增运行时3D库或后端。轻3D采用浅立方体透视、确定性运动及深度排序，无真实物理或逐豆阴影。
- build_gifs.py使用Pillow离线生成2D与烟花；render-3d.cjs复用页面绘制代码、@napi-rs/canvas生成帧，pack_3d_gifs.py打包。离线生成工具不等于浏览器已具备视频编码功能。
- GIF均核对5秒；末帧图纸一致，浏览器检查播放、进度、分组、放大及关闭。3D曾因图片未加载生成空GIF，已改为等待加载并断言有效动画帧后重新输出。
- 3D导出源每版100帧/20fps，GIF压缩合并相同帧后实际帧数可减少；仍为5000ms。300张中间帧已在验证后清理，保留脚本和过程静帧，可重新生成。
- 2708颗、三版同时播放时Canvas绘制中位数实测约20.5～25.1ms、P95约29.6～36.8ms，可能慢帧；不包含完整合成/编码成本，不代表手机或更大图纸。不能承诺“几乎不耗性能”。
- 切后台暂停，目标上限30fps，放大时仅绘制所选版；尚未实现正式性能降级或跨设备验收。

## 4. 视频与Live图导出：讨论结论，尚未实施

- 用户希望动画导出项与图片在同一弹窗显示，可一起播放或悬停播放。助手建议封面加悬停/键盘焦点预览，触控提供播放按钮；尚未确定交互。
- 建议MP4/H.264、SDR、不透明背景、720×1280、30fps、5秒，图纸等比适配不裁切，首版无音轨；这些是建议，尚非确认输出规格。
- 浏览器播放MP4、浏览器能够本地编码、发起下载、保存到相册、平台成功发布是不同能力，需分别验收。WebCodecs/MediaRecorder需能力检测，不能承诺所有浏览器都能本地输出同一格式。
- 网页分享依赖安全上下文、用户手势及系统分享目标；不等于直接写入相册。服务端转码或原生辅助均未确定，未新增后端或上传素材。
- Live Photo不是改后缀的视频：需静态图、视频及关联元数据；即使生成正确文件对，网页下载/分享也不能保证系统自动合并成相册实况。
- 不可靠来自完整链路：网页相册导入能力、系统/厂商格式差异、文件元数据、平台发布入口对实况的保留共同决定；不是简单的设备性能问题。Apple Live Photo与Android动态照片不保证通用。
- 小红书/抖音发布需以目标系统、客户端及入口实测；小程序保存视频文档不证明普通网页或所有发布入口支持。也未承诺5秒文件符合各实况实现要求。
- 具体一手来源链接集中在docs/REPLAY_ANIMATION_DECISIONS.md。

### 正式接入前待明确

1. 继续全图统一动画，还是保留生成/修改分段；轻3D放弃不自动决定此项。
2. 同步播放或悬停播放、键盘及触控行为；多视频勾选、图片和视频混合交付方式。
3. 最终视频尺寸/帧率/背景/音轨，支持的设备、浏览器与发布入口，以及不支持时的处理。
4. 视频单独导出是否保存草稿，混合批次保存/失败重试语义；是否需要原生或服务端辅助。

现有PC仅图片单PNG/多ZIP、PAD/手机旧导出页维持。src/exporter.js、src/features/export-modal.js及export-files.js本轮未修改；没有正式MP4、Live Photo或保存相册实现。
