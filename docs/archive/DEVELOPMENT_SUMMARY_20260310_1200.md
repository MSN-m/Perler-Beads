## 2. 功能变更

### 2.1 智能抖动算法（`src/processor.js`）

**问题**：Floyd-Steinberg 抖动算法全局应用，导致纯色小色块（如爱心）出现多种颜色混杂。

**方案**：两阶段处理 + 快照隔离

- 新增 `isSameColor(color1, color2)`：判断两颜色是否相同（ID 相同 或 RGB 距离 < 30）
- 新增 `shouldEnableDithering(x, y, gridWidth, gridHeight, pixelData)`：检测当前格子周围 8 个邻居，若 6/8 以上同色则判定为纯色区域，返回 false（不抖动）
- **Phase 1**：遍历所有格子，透明度加权采样，初步匹配颜色，存入 `pixelData` 和 `avgColors`
- **Phase 2**：基于 `pixelDataSnapshot`（Phase 1 快照）判断是否需要抖动，只对渐变区域应用 Floyd-Steinberg 误差扩散，纯色区域跳过
- 加入调试日志：`console.log('[SmartDither] dithered: X skipped: Y')`

### 2.2 边缘采样优化（`src/processor.js`）

**问题**：边缘格子采样时混入透明背景像素（alpha=0 的白色），导致边缘格子匹配到错误颜色。

**方案**：透明度加权采样

- Phase 1 采样时只统计 `alpha > 128` 的不透明像素
- 若不透明像素占比 < 30%，整格视为透明（NONE），不参与颜色匹配
- 有效避免了边缘格子被背景色「污染」

### 2.3 色块连通性后处理（`src/processor.js`）

**问题**：颜色匹配本身的误差导致纯色区域内存在 1-2 格的孤立杂色点。

**方案**：新增 `unifySmallRegions(pixelData, gridWidth, gridHeight, minSize)`

- **Phase 3**：在 `generatePatternData` 最后调用，用 BFS 扫描所有连通色块
- 面积 < `minSize`（当前值：2）的孤立色块：统计周围邻居颜色分布，找出接触最多的颜色
- 加入色差保护：只有当孤立色块与目标颜色的 RGB 距离 < 80 时才归并（防止消除有意义的细节，如黑色眼睛）
- 色差 ≥ 80 的孤立格子（如深色细节）保留不变

### 2.4 移除背景按钮可见性修复（`index.html`）

**问题**：设置页 canvas 区域的父容器有 `overflow-hidden`，导致绝对定位的「移除背景」按钮被裁切，用户看不到。

**方案**：将父容器 `overflow-hidden` 改为 `overflow-visible`


## 5. 算法参数说明（供调优参考）

| 参数 | 位置 | 当前值 | 说明 |
|------|------|--------|------|
| 邻居一致性阈值 | `shouldEnableDithering` 返回 `sameColorCount < 6` | 6/8 | 调小（如4）→ 更多区域抖动；调大（如7）→ 更保守 |
| 颜色相似度阈值 | `isSameColor` RGB 距离 | 30 | 调大→ 更多颜色被视为「相同」 |
| 色块最小面积 | `unifySmallRegions` minSize | 2 | 调大→ 消除更大的杂色块，但可能丢失细节 |
| 色差保护阈值 | `unifySmallRegions` colorDiff | 80 | 调小→ 更多细节被保留；调大→ 更激进归并 |
| 透明像素比例 | Phase 1 采样 alpha 判断 | 30% | 调大→ 边缘格子更容易被视为透明 |
