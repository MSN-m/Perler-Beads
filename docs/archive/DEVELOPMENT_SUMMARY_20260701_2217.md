# Development Summary 2026-07-01 22:17

## 本轮目标

本轮没有直接修改产品代码，主要围绕“编辑画布页面工具栏”进行产品结构讨论，明确下一阶段编辑器工具栏的心智模型和技术方向。

## 当前仓库状态

- 归档前工作区为干净状态。
- 当前分支与远端同步：`main...origin/main`。
- 本轮归档仅新增本文档。

## 关键产品决策

### 1. 编辑画布一级工具先保持轻量

围绕编辑画布工具栏，当前更推荐先采用更轻的一级入口：

- 画笔
- 橡皮
- 颜色清单

暂时不单独设置“清理”一级菜单。

原因：

- 当前“移除底色”的真实心智更接近橡皮：按底色颜色批量擦除。
- 当前“边缘调整”的真实心智更接近画笔：识别边缘范围后上色。
- 质量检查、小碎块处理等“清理/优化”类能力计划后期再上，当前不宜提前占用一级入口。

保留未来扩展口：

- 如果后续出现小碎块自动处理、孤立点检查、可拼性评分、耗材优化等能力，再从画笔/橡皮中拆出“清理”一级菜单。

### 2. 画笔职责

画笔的用户心智是：

> 我要把这里改成某个颜色。

建议包含：

- 单点填色。
- 拖动涂抹填色。
- 从图纸吸色。
- 从原图吸色。
- 历史颜色。
- 色板入口。
- 边缘上色。

注意：

- 如果“边缘调整”未来变成自动优化边缘、删除毛边、平滑轮廓，则应重新评估是否迁移到“清理”。
- 当前定义下，边缘功能是“识别边缘后给范围上色”，放在画笔里合理。

### 3. 橡皮职责

橡皮的用户心智是：

> 我要擦掉不需要的豆子。

建议包含：

- 单点擦除。
- 拖动擦除。
- 按颜色移除。
- 移除底色。

注意：

- “按颜色移除”和“移除底色”是批量破坏性操作，需要确认或至少可撤回。
- “移除底色”可以视为“按颜色移除”的快捷预设。

### 4. 颜色清单职责

颜色清单不应被理解为单纯编辑工具，它更像材料统计和颜色管理入口。

建议保留现有每个颜色后的菜单能力：

- 查看用量。
- 高亮该颜色。
- 替换同色。
- 替换相近色。
- 从颜色清单发起颜色相关操作。

颜色清单可以继续承载高级颜色操作，但不必成为用户编辑的主入口。

## 统一编辑会话决策

### 1. 问题判断

当前每个编辑工具里都有“确认 / 撤回 / 取消”的流程感，会让操作显得笨重。

问题本质：

- 每个工具都像一个独立小流程。
- 用户换一次工具就像进入/退出一次模式。
- 手机和 iPad 上会放大这种心智负担。

### 2. 方向确认

决定将“确认 / 撤回 / 取消”抽离为全局统一编辑指挥，而不是挂在每个工具下。

推荐交互心智：

1. 用户进入编辑图纸。
2. 用户连续使用画笔、橡皮、色板、按颜色移除、边缘上色等工具。
3. 每个真正改变图纸的动作自动进入统一历史栈。
4. 用户可以随时全局撤回。
5. 最后统一点击完成提交全部改动，或取消放弃本次编辑会话。

换工具、换颜色不应要求确认。

### 3. 技术可行性

当前项目已有接近该方向的地基：

- `stagedPixelData`：编辑暂存区。
- `stagedActions`：撤回栈。
- `adjustUndo()`：撤回。
- `adjustCancel()`：取消。
- `adjustApply()`：确认写回正式 `pixelData`。

下一步不一定立刻大重构，但概念上应将这些从 `adjust` 专用升级为统一编辑会话。

建议目标模型：

```js
editSession = {
  active: true,
  pixels: stagedPixelData,
  undoStack: stagedActions,
  redoStack: [],
  activeTool: 'brush' | 'eraser' | 'palette' | 'replace' | 'edge',
  currentColor: null
}
```

可以先沿用现有字段实现，不必马上新增完整对象。

### 4. 建议规则

- 进入任意编辑工具时，如果还没有编辑会话，就创建 `stagedPixelData`。
- 切换画笔、橡皮、色板时，不结束编辑会话。
- 单点填色、拖动涂抹、单点擦除、拖动擦除、按颜色移除、边缘上色，都作为 action 进入 `stagedActions`。
- 全局撤回撤销最近一个 action，不区分来自哪个工具。
- 全局取消丢弃整个 `stagedPixelData`。
- 全局完成将 `stagedPixelData` 写回 `pixelData`。
- 颜色选择本身不是 action，除非它实际修改了图纸。

### 5. 需要防范的风险

最大风险：

- 用户以为改动已经保存，但实际仍在暂存区。

短期建议：

- 保留清晰的“编辑中”状态。
- 保留全局“完成 / 取消”。
- 不在当前阶段改成完全自动保存。

未来如果要进一步轻量化，可以考虑让所有操作直接写入正式图纸，并用全局 undo/redo 保护，但这会比当前改造风险更大。

## 下一步建议

1. 先整理现有编辑相关函数和状态：
   - `editMode`
   - `stagedPixelData`
   - `stagedActions`
   - `adjustUndo`
   - `adjustCancel`
   - `adjustApply`
   - `handleResultCanvasClickForAdjust`
2. 将命名和 UI 心智从“颜色调整专用”逐步升级为“统一编辑会话”。
3. 工具栏先按轻量一级结构推进：
   - 画笔
   - 橡皮
   - 颜色清单
4. 操作栏独立为全局编辑状态栏：
   - 撤回
   - 取消
   - 完成
5. 做连续画笔/橡皮前，先设计 action 数据结构：
   - 单点操作。
   - 拖动批量操作。
   - 按颜色批量操作。
   - 边缘上色批量操作。

## 备注

本轮结论不是为了追求极简而删功能，而是为了先建立“画、擦、选色、统一撤回/完成”的核心编辑器心智。后续等质量检查、小碎块处理等能力成熟后，再拆出“清理”菜单会更自然。
