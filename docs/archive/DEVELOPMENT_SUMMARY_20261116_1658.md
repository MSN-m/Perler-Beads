# 开发归档｜手机裁剪、图纸预览与加载反馈

归档时间为 2026-11-16 16:58（Asia/Shanghai）。上一份归档为[手机首页与草稿弹窗](DEVELOPMENT_SUMMARY_20261115_1903.md)。本轮以提交 `225da23` 作为工作区变更基线。

## 本轮改动

### 手机首页与草稿

- 让新版「小豆鸡」首页在应用脚本初始化前显示，避免手机网络或脚本较慢时先露出「生成设置」。
- 修复草稿卡片横滑只抖一下的问题。横滑过程中保持由按下的卡片持有指针捕获，避免转交捕获时产生的事件提前清掉手势。保留侧卡点击、左右循环及打开当前卡片。
- 临时预览曾提供 `/demo-drafts.html`，给同一浏览器来源添加三份独立的可编辑示例。重复导入跳过同 ID 的记录。手机和 Mac 内置浏览器各自管理本地草稿。

### 上传、裁剪与图纸设置

- 按 Figma `788:2` 接入手机「上传图片」页面。裁剪和图纸设置同页，图片调整复用现有亮度、对比度、饱和度和重置。同步图纸名称、品牌、尺寸和颜色上限的显示，两个设置标签底部增加留白。
- 右侧从上到下为确认、撤回、取消。确认应用当前范围并保留裁剪能力，可以在当前图内继续裁切。撤回逐次恢复上一范围，取消清除当轮未确认的框选。裁剪和撤回坐标沿用原图坐标。
- 手机长边提供 40、70、100 格，默认 40 格，短边等比四舍五入且至少 1 格。颜色上限提供 4、8、12、16 色，默认 4 色。从设置页返回首页先确认，确认后丢弃本次图片、裁剪、设置和修改记录。

### 图纸预览与加载

- 按 Figma `797:199` 接入手机「预览图纸」页面。显示实际使用色数，提供「原图」「卡通」「照片」和按识别结果可用的「像素」。返回保留本次设置及已选效果，进入编辑直接使用确认的预览数据。PC、PAD、手机上传新图后统一默认「原图」。PAD 的效果列表继续提供三种常规预设。
- 上传复用初始图像像素，合并自动裁剪的透明度与颜色扫描。手机实时调色使用显示尺寸画布并复用预览像素，正式生成继续读取原始分辨率裁剪数据。
- 首次生成复用相同格尺寸的像素权重，降低颜色分桶与格线检测的扫描开销。手机同一轮的常规效果共享采样统计，已生成的效果直接从该轮缓存读取。重新开始预览按当前设置计算。
- 手机普通预览先渲染，像素画判断交给 Web Worker。Worker 不可用时先显示普通预览，再回退识别。返回、换图或进入编辑时清理旧任务。
- 选图时显示普通转圈。「预览图纸」依实际阶段显示「小豆鸡在给豆豆点名…」「小豆鸡在给豆豆排队…」「小豆鸡在鼓励走错的豆豆…」。画布就绪即关闭，无固定文案停留时间。切换到当前会话尚未生成的「像素」效果时同样显示反馈，直接读取结果的效果切换即时更新。加载期间拦截重复提交，生成失败保留设置以便重试。

## 验证与已知问题

- 用隔离内置浏览器及合成图片检查了手机首屏、模拟草稿横滑、连续裁剪和撤回、横竖图及细长图尺寸、返回保留、实际色数、规则像素图、后台检测取消和回退。三端模拟视口均确认「原图」默认。对比优化前后裁剪范围和测试图的预览结果，结果逐格一致，进入编辑使用确认的预览数据。
- 内置浏览器的手机视口里，用一张 4032×3024、约 10 MB 的合成图比较多项性能优化前后。选图到裁剪可用的三次中位数为 149 ms 和 90 ms。该轮首次预览为 896 ms 和 244 ms，常规效果切换从 881–1212 ms 降到 2–7 ms。另一个 4032×3024 测试中，先出普通预览、后台做像素检测的前后点击耗时为 157 ms 和 106 ms。两组结果来自各自的样本和基线，均为 Mac 模拟视口记录。
- 最终加载反馈在本机预览的手机视口检查通过，覆盖坏文件、标准转圈、三句文案顺序、重复点击、画布完成即关闭、快速切换、生成失败和重试。一个小图样本从点击到完成约 3 ms。PC 预览流程也做了冒烟检查。本轮没有重新跑整套 Node 测试。
- 草稿横滑的手机实机手感、触控板手势、大图处理与加载文案的实机体验，以及非规则像素画的主色取样仍待专项复验。
- 旧局域网服务已停止。自动审批拒绝重新开启会提供整个临时项目目录的服务。目前只核验了回环地址 `http://127.0.0.1:8080/`。本轮测试用临时页面已清理，手机实机访问仍待恢复。
- 固定标尺本轮没有相关改动或专项回归。PC 的顶部遮挡和数字密度修正仍待浏览器验收。PAD 和手机尚未同步固定边缘、坐标跟随、刻度密度和对照边界，触控及既有标尺可用性仍需核查。
