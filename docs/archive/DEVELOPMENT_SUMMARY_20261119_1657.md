## 功能变更与产物

- 按用户指定下载并在工作区安装小工具构建 Skill 1.11.1，位于 `.codex/skills/minitool-zip-builder/`，核对小工具在线能力文档；专用构建从正式源码生成独立离线 ZIP。
- 小工具适配采用经典外置脚本、包内资源、Chrome 61 目标与局部兼容回退，处理 CSS、Worker 和运行时限制。平台 Storage 采用不可变分片与指针提交，保存失败保留旧记录，不回退浏览器数据库。
- 用户确认同时提供「保存到相册」与「发作品」，已在小工具专用适配中实现。共用三类图片多选，先保存草稿，失败阻止输出；发布回执仅代表提交，不代表审核通过。网页原导出保持。
- 手机首页按用户截图调整：居中品牌与标题、示例区配色、底部并排草稿/上传入口。小工具首页根据 getWindowInfo 返回的可见按钮矩形避让顶部；不重复增加状态栏高度。没有接管原生返回，也没有改造正式应用的导航结构。

## 返回实验与确认结论

- 独立实验源码位于 `experiments/navigation-probe/`，不读取或修改正式图纸、草稿。A 使用 pushState/popstate，B 使用 hash/hashchange，C 使用两个 HTML 实际跳转。
- 交付 `outputs/back-button-test/01-标准返回测试-A和B.zip`（4,896 字节）和 `02-多页返回实验-C.zip`（5,624 字节）；附使用说明、校验摘要、校验和与本地截图。C 从开始即标为不用于正式发布的兼容性实验。
- 本地内置浏览器三种方式均能从第二页返回第一页；用户随后反馈 A、B 在小红书顶部返回均直接退出小工具。手机型号、系统和客户端版本未提供，不能写成 Android/iOS 全覆盖验收。
- C 被平台拒绝，用户截图明确要求只保留根目录 index.html、删除其他 HTML。这是平台限制，不能继续把多 HTML 拆页作为小工具方案，也不能用静态审计通过抵消上传结果。
- 网页浏览器返回与小红书原生顶部返回必须分开判断。单 HTML 可以组织多个界面并建立网页历史，但已测 A/B 未解决原生退出；专门返回控制接口尚未最终核实，不能宣称所有代码方案均不存在。

## 设计决定与未实施计划

- 用户同意以弹窗/面板形式承载后续步骤，用一致、明显的内部返回/关闭按钮引导操作，降低误点系统退出；编辑画布保留空间。该方向尚未实施，不能描述为已经改变系统返回行为。
- 已向用户提出进度保存计划：覆盖上传后的图片、确认裁剪和设置；生成完成保存一次，完整编辑操作结束后约两秒合并保存；首页提供「继续上次制作」；显示保存中/成功/失败，保留上一份成功记录，自动进度不占三个手动版本。
- 用户只要求说明上述计划，尚未授权实施。现有正式自动恢复仍约五分钟检查保存，仅覆盖已生成图纸，不覆盖完整生成前会话；不因本次归档改变保存频率、格式或首页恢复入口。
- 小工具顶部没有已确认的统一导航栏高度。此前回答的 44px 导航/88px 合计是通用设计参考，已向用户纠正，不能当作平台尺寸。官方 getWindowInfo 提供容器坐标下按钮矩形与安全区，375×812 不能单独确定实际高度；当前手机准确数值尚未读取。
