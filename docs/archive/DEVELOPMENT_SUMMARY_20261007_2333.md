# 开发归档：导出弹窗多选与返回首页规划

时间：2026-10-07 23:33（Asia/Shanghai）

## 1. 本轮变更

本轮仅讨论产品交互并归档，未修改前端代码、导出算法或草稿数据。本次编辑文件为docs/PROJECT_CORE.md、docs/PRODUCT_GUARDRAILS.md及本归档。

## 2. 已确认的方向

- 将现有三个保存按钮改为导出弹窗内的多选项，单个导出按钮触发所选多张图片分别下载，不采用ZIP。用户明确先不要改代码。
- 名称第三项先采用“无标注图”。第一项希望四字名称，附件使用“拼豆图纸”；第二项为“镜像图纸”。第一项最终命名仍待确认。
- 用户期望引导保存后回到首页。
- 用户附件是弹窗大体逻辑参考：标题“导出图纸”、大预览、三种可勾选卡片、关闭按钮及导出主按钮。截图中的镜像选中不是已确认的默认值。

## 3. 文案与按钮建议：尚未明确采纳

- 拼豆图纸：含网格与色号，方便对照拼豆。
- 镜像图纸：左右翻转，含网格与色号。
- 无标注图：不含网格与色号，适合展示。
- 导出前主按钮“导出图纸”，旁注“导出时同步保存草稿”。
- 下载已发起且草稿保存成功后显示“下载已开始，草稿已保存”，按钮改为浅色“继续编辑”、粉色主按钮“返回首页”。
- 保留弹窗，让用户主动返回而非下载后立即跳首页，以便处理多文件下载许可。保存失败留在弹窗提示重试。

这些为助手建议；一键归档仅保存讨论，不视作实施授权，也不视作用户逐项确认文案。

## 4. 待明确事项与风险

- 第一项最终四字名称、各副标题、默认勾选与至少一项选择规则。
- 预览展示标准/镜像/无标注哪一项，多选时如何切换预览。
- 两阶段按钮是否采用，关闭、Esc、遮罩与继续编辑的行为，以及首页真实入口。
- 多选导出每次保存一次草稿是建议；仅无标注图是否同步保存需确认。目前对应保存原图仍只下载，不能擅自改变。
- 浏览器可能要求允许多文件下载；网页只能可靠报告下载已发起，不能保证文件已落到磁盘。需明确重复下载与部分生成失败的处理。
