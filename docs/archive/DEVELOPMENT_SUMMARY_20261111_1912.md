## 已确认交互

| 页面 | 决定 |
| --- | --- |
| 首页 | 「上传图片」固定在底部，示例列表底部预留空间。点击示例直接进入编辑器，可修改当前图纸，也可走对应环境的输出流程。 |
| 我的草稿 | 左右循环横滑大卡片。第一张向右翻是第二张，向左翻是最后一张；只有一份时不切换。首版暂不加重命名、删除、历史版本菜单。 |
| 上传图片 | 裁剪和图纸设置同页。点「预览图纸」时应用当前框，返回保留裁剪框和设置。以裁剪框长边为基准，设 40、70、100 格三档，短边同比缩放、四舍五入且至少 1 格。按钮随裁剪框更新宽×高，例如宽高比 2:3 时为 27×40、47×70、67×100。4、8、12、16 色均为上限。 |
| 预览图纸 | 显示实际使用色数，保留「原图」「卡通」「照片」名称。手机开放「像素画」，沿用原有识别后可选的规则和默认效果。主按钮叫「进入编辑」，将当前预览结果直接带入编辑器。 |
| 编辑器退出 | 有未保存修改时提供「保存并返回」「不保存并返回」「继续编辑」。保存成功后才返回，失败留在编辑器；没有未保存修改直接返回。 |
| 小红书发作品 | 通过原生笔记发布页发作品，首版无本地输出入口。点「发作品」同时保存当前草稿。按保存版本内部区分「仅保存」和「已提交发布」；手动保存或取消发布属于仅保存，收到提交回执后才记为已提交发布。列表首版统一展示，最终审核由平台处理。 |

2026-09-27 的实现将「像素画」限定在 PC。当前代码在生成预览时已经做识别，但按钮与效果选择都有桌面条件，手机开放尚待实现。未查到手机性能问题是当时限制的原因。PAD 未纳入本次开放范围。

## 平台准备与验证边界

- 已安装 Windows Codex 用户级 `redapp-cli` 和 `minitool-zip-builder` 1.10.0，Codex 重新扫描识别并启用了两套 Skill。文件位于用户的 `.codex/skills/`，不在项目仓库。
- 管理 CLI 正式版 1.0.5 的版本门禁通过。用户完成小红书扫码授权，`redapp whoami --agent` 返回 `ok`。本轮未创建、上传、生成远端预览或送审任何小工具。
- 现有网页入口已用包内 Tailwind CSS。小红书交付仍需处理内联 import map、ES Module、目标 WebView 的 JS/CSS 兼容，以及容器内的草稿存储和原生 `postNote` 输出。网页端原有下载和存储语义按现行规则保留。
- 小工具公开 API 清单未列出自定义事件上报，网页容器也限制外部请求。Builder Hub 登录后是否有小工具专属统计及其指标范围尚未核验。产品入口为 [Builder Hub 小工具管理页](https://creator.xiaohongshu.com/new/red-app)，运行规则见[小工具容器能力清单](https://miniapp-sandbox.xiaohongshu.com/minitool/doc)。
- 本轮仅核对源码和规范，未改动应用、生成 ZIP 或完成小红书模拟器、iOS、Android 真机验收。
- 设计评审依据用户提供的四屏截图。后续可用逐页 PNG、交互录屏和关键尺寸或 CSS 继续交接设计，也可提供有查看权限的 Figma 原型链接。

## 已知限制与下一步

1. 先按确认稿推进现有移动端，逐步验证示例、草稿循环、裁剪与返回、尺寸与颜色上限、预览结果进入编辑，以及编辑退出保护。实现前按仓库规则说明受影响的流程和回归范围。
2. 新版手机默认尺寸档位待确定。像素画需要用规则像素画、非规则像素画、普通照片、渐变和透明图核对识别及结果，并实测手机切换耗时。
3. 核心流程稳定后，从同一份源码构建小红书包，按交付时的官方规范校验。平台模拟器和 iOS、Android 真机覆盖选图、生成和编辑、保存重开、发布取消与提交，并回归网页端原有导出。
4. 继续保留上一份归档的历史待办，尤其是固定标尺 PC 专项及 PAD/手机同步、真实触控、五分钟自动记录及恢复、浏览器退出保护、实际导出和 Figma 权限等。未确认「不保存并返回」是否清理自动恢复记录。
