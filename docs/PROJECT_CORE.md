## 1. 产品定位

这是一个面向拼豆爱好者的图纸生成与编辑工具。用户上传图片，确认裁剪范围，选择拼豆品牌、图纸尺寸和颜色数量后生成可制作、可编辑、可导出的拼豆图纸。

长期目标不是只提供图片转图纸，而是形成拼豆制作过程的辅助闭环：图纸生成、制作辅助、颜色与步骤管理，以及未来的社区能力。

## 2. 核心用户流程

1. 上传图片或打开草稿。
2. 确认生成范围并裁剪图片。
3. 设置图纸名称、拼豆方案、像素密度和颜色限制。
4. 生成预览并选择生成效果。
5. 进入编辑画布，查看图纸、颜色清单和原图对照。
6. 使用画笔、吸管、橡皮、全部颜色、颜色清单等工具调整图纸。
7. 保存草稿或导出图纸。

## 3. 端与布局原则

| 端 | 主要定位 | 当前原则 |
| --- | --- | --- |
| PC | 精细编辑与完整信息展示 | 画布优先，顶部为项目与全局操作，底部为编辑工具栏。 |
| PAD | 拼豆制作和轻量编辑的重要终端 | 保留大画布与触控操作空间，面板以弹窗/抽屉呈现，不长期挤占画布。 |
| 手机 | 上传、设置、浏览和轻量修改 | 使用分步流程；裁剪、设置、生成与编辑的状态要明确，底部主要操作常驻。 |

三端可以拥有不同的布局和视觉样式，但必须复用相同的业务状态、数据结构和核心功能语义。

## 4. 图纸生成

### 当前正式流程

正式页面使用网格化拼豆生成流程：

`裁剪图像 -> 网格采样 -> 品牌调色板匹配 -> 颜色数量限制 -> 可选抖动 -> 小区域清理 -> 图纸渲染`

相关实现主要位于 `src/processor.js`，正式页面通过 `src/ui.js` 调用。

### 当前正式方案与后续方向

- 当前 `index.html` 正式流程使用现有 `generatePatternData()` 网格化拼豆方案；这是用户确认继续采用的正式方案。正式默认流程保持不变。
- “中强度区域级扁平化 + 主体与背景分离”曾作为后续候选方向讨论，目前暂时放弃，不再作为已确认的正式路线或待接入事项。若未来重新评估，需重新取得用户确认并完成实验验证。
- 实验页结果不得直接替代当前正式方案；任何调整正式默认算法的工作，都需要用户明确确认并通过对应评测。

### PC 像素画预览选项

- 生成预览阶段的“像素画”是 PC 端可选效果，不改变默认效果，也不开放于 PAD 和手机端。
- 若检测到规则原格，按识别到的像素格取样；若没有可靠原格、但检测到明显像素画特征，则按每个拼豆格覆盖区域内出现最多的颜色取样，不启用抖动和小区域清理。
- 未检测到像素画特征时，该选项不可用。检测属于启发式判断，不能保证识别所有像素画，也可能存在误判；预览提示应说明采用的取样方式。
- 用户确认预览后直接使用同一份预览结果进入图纸，避免预览与最终图纸算法不一致。
- 当前识别与主色取样已在处理器内实现；附件猫图的检测检查通过，但浏览器完整交互尚待验收。详细记录见最新开发归档。

### 实验页面

- `algorithm-lab.html`：多种图纸生成策略的对比实验。
- `flatness-lab.html`：图片扁平化加工实验页；保留区域级扁平化探索，不代表当前已确认的正式方向。用户可处理图片并下载本地 PNG，不进行拼豆色板匹配。
- `combined-lab.html`：按“原图 -> 中强度扁平化 -> 主体保护型映射 -> 图纸”展示组合流程与正式基准的同条件对照。当前结果存在颜色发乌、还原精准度不足的问题，仅保留用于定位问题，不能代表最终组合方案效果。
- `algorithm-lab-complete.html`：保留原八组策略页之外的独立实验版本；为主体/背景、全局颜色、形状优先、可制作性等策略提供启发式实现。当前尚未通过颜色和精准度评测。
- `algorithm-lab-final.html`：组合候选算法测试页，用于对照主体掩码、轮廓层、正式基准和最终候选；不属于正式生成流程。

最终候选算法的人工验收使用 `docs/FINAL_CANDIDATE_ALGORITHM_TEST_CHECKLIST.md` 和 `outputs/20260824_algorithm_test_matrix/最终候选算法_覆盖图片测试矩阵.xlsx`：前者定义逐图检查项，后者将图片类型与背景、透明度、光照、纹理、细节等特征组织为覆盖矩阵，并提供记录页。

实验页的结果不应直接作为正式生成器输出，也不能在没有评测和确认的情况下替换 `generatePatternData()`。

## 5. 编辑器功能定义

编辑器以全局撤销/重做和暂存数据为基础，修改完成前不应破坏正式图纸数据。

| 功能 | 定义 |
| --- | --- |
| 画笔 | 使用当前颜色修改一个或连续多个图纸格；拖动可连续上色。进入取色绘制流程时，也可先从图纸取色。 |
| 油漆桶 | 将点击格所在的上下左右相连、且颜色相同的区域填成当前颜色。 |
| 边缘上色 | 选择一种颜色并批量修改整张图案轮廓边缘的豆子；与局部颜色区域的边框并非同一语义。 |
| 吸管 | 从画布或开启对照时的原图取色，作为当前画笔颜色；成功取色后切回画笔。 |
| 橡皮 | 已接入单格/连续拖擦、上下左右连通的同色区域擦除、悬停高亮后整色擦除；一次操作对应一条全局撤销，保留至少一颗豆子。自动检查通过，PC 浏览器专项验收待完成。 |
| 拖动画布 | 目标行为为独立、持续生效的拖动工具，直到切换其他主工具；PC 主栏已接入该模式，仍待布局与浏览器验收。 |
| 颜色清单 | 显示图纸中实际使用的颜色；点击颜色可高亮画布中的同色格。 |
| 全部颜色 | 显示所选品牌的完整色板；选择颜色后切换为画笔当前颜色。 |
| 最近颜色 | 最近选中的 5 色，按色号去重、最新置左，不足显示空槽；选色不进入图纸撤销栈。PC 已完成本轮逻辑回归。 |
| 原图对照 | 在编辑阶段查看裁剪后的原图，用于核对图纸。 |
| 撤销/重做 | 控制全局编辑历史，不属于单一工具的二级动作。 |

### 已确认的固定标尺规则（实现待验收）

- 仅显示顶部和左侧标尺，标尺条固定在编辑画布可视区域边缘；图纸平移时刻度和数值随图纸移动，坐标起点始终对应图纸起点。

## 6. 草稿与导出

- 草稿保存当前图纸、生成设置、裁剪信息和必要的源图快照。
- 草稿可恢复、导出和删除，也支持导入草稿数据。
- 导出图纸包含图纸名称、网格、色号和颜色统计。
- 未填写图纸名称时使用“未命名图纸”作为显示与导出占位。

## 7. 技术结构

- 技术栈：HTML、Vanilla JavaScript ES Module、Tailwind CSS CDN、Canvas；无构建工具、无后端。
- 入口：`index.html`。
- `src/main.js`：DOM 事件绑定与应用入口。
- `src/state.js`：全局 `AppState`。
- `src/ui.js`：工作台状态、生成流程、面板和交互协调。
- `src/processor.js`：图像处理、采样、调色板匹配、抖动、实验算法。
- `src/renderer.js`：图纸 Canvas 渲染与缩放坐标。
- `src/editor.js`：编辑器会话、全局撤销重做、颜色统计和批量替换。
- `src/exporter.js`：图纸导出。
- `src/constants.js`：MARD、Perler、Hama、Artkal 调色板数据。

## 8. 关键数据与约定

- `AppState.pixelData`：当前正式图纸像素数据。
- `AppState.stagedPixelData`：编辑暂存图纸数据。
- `AppState.stagedActions`：暂存编辑操作记录。
- `AppState.editor.undoStack / redoStack`：全局编辑历史。
- `AppState.gridWidth / gridHeight`：图纸网格尺寸。
- `AppState.brand / mardSet`：拼豆品牌与 MARD 规格。
- `AppState.zoomState`：画布缩放与平移状态。
- `AppState.highlightedColorId`：颜色清单高亮状态。

图纸点击和绘制使用内容包围盒坐标系，具体换算规则以 `AGENTS.md` 为准；修改画布事件前必须先阅读该约定。
