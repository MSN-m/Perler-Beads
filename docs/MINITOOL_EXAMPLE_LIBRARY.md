# 小红书示例图纸库更新方法

仅小红书小工具使用分组库，普通网站继续原来的六张示例。

## 当前展示（2026-11-25更新）

- 用户确认暂不采用新的首页示例分组UI，恢复六张图纸平铺：草稿1、柯基、草稿10、9、8、7，不显示「最新图纸」或分组条。
- 当前配置使用顶层 `patterns`；分组代码保留，未来UI方案确认后再通过 `groups` 启用，不能自动恢复分组展示。
- 点击图纸时才创建编辑像素数据，继续使用原有示例打开入口。

## 最方便的更新方式

把工具导出的图纸 JSON 按文件夹分组后压缩为 ZIP，交给助手，同时说明：

> 用这个 ZIP 更新小红书示例库。文件夹名作为组名，分组顺序为……，组内按文件名排序。「……」组默认展开。替换现有示例（或保留现有示例）。只更新代码和预览，先不要生成发布 ZIP。

可以用 `01-小动物`、`02-花草` 给文件夹排序；如果编号只用于排序，请明确说明显示时去掉编号。名称以后都能改。一个文件夹就是一组，每个 JSON 对应一张图纸。导出 JSON 即使带有原图或历史，也只提取当前图纸，不导入为用户草稿。

## 直接维护仓库

配置：`assets/data/minitool-examples/catalog.json`。

```json
{
  "groups": [
    {
      "id": "latest",
      "title": "最新图纸",
      "defaultOpen": true,
      "patterns": ["latest/draft-1.json", "latest/corgi.json"]
    },
    {
      "id": "animals",
      "title": "小动物",
      "patterns": ["animals/cat.json"]
    }
  ]
}
```

这个例子需先创建 `animals/cat.json` 才能通过校验。

- `groups` 数组顺序就是分组顺序，`patterns` 数组顺序就是组内顺序。
- `title` 是显示名称，可以随时改；`id` 是唯一标识，只用小写英文字母、数字和短横线，建议保持稳定。
- 有分组时必须且只能有一个组设置 `defaultOpen: true`；其他组省略或设为 `false`。
- 每张图纸独立保存到配置目录内的 JSON，方便 Git 只记录变更的文件。不同组可以引用同一图纸文件。
- 文件采用精简结构：`name`、`gridWidth`、`gridHeight`、`brand`、`mardSet`、`colors`、`indices`。其中 `colors` 是 `[色号,r,g,b]` 数组，`indices` 是逐格颜色索引，长度必须等于宽×高，透明色号为 `NONE`。
- 工具导出的草稿 JSON 需要先转换成上述精简结构，不能直接复制进库。可将原始文件交给助手转换；不要手工修改格子索引。
- 删除图纸时先删除配置中的引用，再删除不再被其他组引用的文件。正式数据为空的组先不要加入配置。

没有分组时，在配置顶层写 `patterns`，并省略 `groups` 或设为 `[]`。这时所有图纸直接展示，不创建「最新图纸」或其他分组标题，例如：

```json
{
  "patterns": [
    "latest/draft-1.json", "latest/corgi.json",
    "group-1/draft-10.json", "group-1/draft-9.json",
    "group-1/draft-8.json", "group-1/draft-7.json"
  ]
}
```

文件夹仍可用于整理文件，是否显示分组以 `catalog.json` 的配置为准；有 `groups` 时只读取组内引用。小工具 iPad 首页使用同一份配置，竖屏三列、横屏四列，按钮位于宣传语下方并随内容滚动。手机仍保留原底部按钮。

更新后校验：

```sh
python3 scripts/minitool_examples.py
node --test tests/minitool-examples.test.mjs
```

构建器会自动把每组转换为独立的经典脚本，主脚本只包含组名、数量和路径，不再内嵌全部示例。无需手工维护生成脚本。

需要编译预览时，沿用 `scripts/minitool/README.md` 的固定版本工具参数，并追加 `--preview-only`；这会生成预览目录并执行静态审计，不创建 ZIP。只有明确要求发布打包后才生成新 ZIP；已有 ZIP 不会随源代码自动更新。

## 发布与验证

示例库随小工具版本更新，Git 同步本身不会更新用户端。新分组和图纸需要重新打包、上传发布；整个离线包仍需包含全部分组文件。

回归检查：默认展开、其余组未提前请求、切换/收起释放、快速切组、失败重试、组内分页、示例打开/编辑/保存、上传与我的草稿入口，以及普通网站/PC/PAD保持原行为。

内置浏览器只验证页面和逻辑；创服平台模拟器、Android/iOS 真机的包内脚本加载、触控和性能，以及 Chrome 61 仍需验证。
